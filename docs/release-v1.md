## 2. 产品范围

- 选购问题，例如卧室噪音、户型与机型选择。
- 使用问题，例如首次使用、模式选择、App 与日常操作。
- 保养问题，例如主刷、滤网、拖布、水箱和传感器清洁。
- 故障排查，例如吸力下降、频繁暂停、木地板翘边和回充失败。
- 回充深挖，例如找不到充电座、手动放回能充、自动回充未测试、恢复确认和未解决转人工。

当前只覆盖这 6 份通用资料。没有品牌官方授权售后，没有设备控制、账号、订单或外部工单工具。

## 3. 闭环能力

### 3.1 检索证据

回答中的关键事实带方括号文件名。售后状态面板显示本轮来源文件名和片段。零命中时工具返回明确的资料不足提示，提示词要求先说明资料不足再追问，不伪造来源。

引用检查只判断回答有没有来源，以及来源是否出现在本轮检索中。它不判断每个事实是否被对应片段支持，不能写成引用准确率。

### 3.2 会话状态与来源作用域

回充故障按会话持久化当前问题、已试步骤、未试步骤、下一步、能力观察、来源作用域和结案状态。用户明确执行过的动作才进入已试步骤，助手建议不自动变成用户事实。

条件句、假设情境和第三方描述受来源作用域约束，不会自动记成当前用户观察。来源片段只在本轮检索存在时展示，缺失时明确提示本轮没有可展示片段。

### 3.3 更正与重启

用户后续更正会撤回之前的已试动作和推导结果，原始轮次、原话和替代原因保留在审计中。否定、更正和重复表达共用同一套事实归约逻辑，避免已试与未试同时存在。

服务重启后重新打开同一会话，售后状态和转人工摘要保持稳定。`GET` 与 `POST /api/sessions/{id}/handoff-summary` 返回同一只读投影，读取摘要不写状态。已结束或已结案会话仍可读取摘要。

### 3.4 未解决转人工

回充案例的摘要包含当前问题、用户原话、轮次和消息 id、实际执行动作与结果、明确没试过的步骤、能力观察、助手建议、未知项、下一步和结案边界。助手建议单独标注，不写成用户事实。

非回充问答没有回充故障案例时，摘要按 transcript 给出当前问题与最近回答原文摘录，并明确没有形成故障状态，不推断设备、已试步骤或原因。

摘要只在本地整理，不会自动发送。界面支持复制、UTF-8 `.txt` 下载、失败重试，切换会话或发送消息会清空旧摘要。下载文件名使用安全会话标识。

## 6. 命令参考

固定入口是 8902。下面的命令在 `robot-vacuum-support` 根目录执行，使用 conda 解释器。助手只读这一份配置，不接收任意配置路径，不重建产物。

```powershell
$py = "C:/Users/28980/anaconda3/envs/langchain/python.exe"
Set-Location "E:/CODE/Myproject/agent-workspace/robot-vacuum-support"

# 状态，JSON 便于记录 PID 和身份
& $py scripts/manage_product.py status --json

# 启动。已在运行时会采纳现有实例，不重启
& $py scripts/manage_product.py start

# 停止。仅用于明确维护，当前保持 8902 运行时不执行
& $py scripts/manage_product.py stop
```

`start` 使用当前 conda 的 `sys.executable`，以 `CREATE_NO_WINDOW` 隐藏启动，日志与 PID 写在 `outputs/release-v1/service/`。启动后轮询 `/api/instance` 和 `/api/health`，只有实例身份、产物身份、进程命令和就绪状态都匹配才报告成功。端口被其他进程占用时拒绝启动，也不会停止对方。

`stop` 会先通过 `/api/instance` 核对 `instance_id` 和 `artifact_id`，再核对进程命令是否指向固定产物与固定配置。任一不匹配就拒绝停止并保留进程。只有两项都匹配且没有待处理请求时才执行停止。

旧 8900 和 8901 已在 2026-11-15 按身份与命令校验停止，存储目录和旧 artifact 原样保留，没有迁移 session。停止记录见 [retired-services.json](standalone.md#未包含)。8900 当时有 2 个已完成会话，没有排队或运行中的请求，8901 没有会话。
